# UI/UX 全面改善 — 調査・監査・方向性 (Phase 1〜4)

2026-09-23。コードは変えていない。ここで決めたことを Figma で確かめてから実装する。

**決まったこと (2026-09-23)**
- Figma を「デザインを決める場所」にし、Figma の MCP (公式の Figma コネクタ) をこのアプリにつなぐ。
  コネクタは Figma を**読む**もの (変数・部品・画面・スクリーンショット) なので、Figma 上で画面を組むのは本人。
  Claude は Figma を読んで、トークンと部品をコードに 1:1 で写し、差分を確かめる
- 画面幅: **PC とタブレット**。1,024px 以上は編集をすべて使える。それ未満 (タッチ PC を縦・画面を半分) はパネルを重ねて開く。
  スマホは閲覧と書き出しだけ
- Figma は無料 (Starter) プランで接続が月に数回しか使えないため、組み立ては `design/figma-plugin/` のプラグインで行い、
  確かめるときはプラグインの「確認用の画像を保存」の画像を使う (接続は使わない)

**決まったこと (2026-09-23 午後): 編集画面は案 B「図を最大に」**
(案と画面: <https://claude.ai/artifact/MVVYdwkussyft1Dec7sW2v>。ほかのソフトの参考は下の 4.2)
- **図そのもの (Word / PowerPoint に貼る図の中身・見た目) は今のまま**。変えるのは図のまわりの画面だけ
- 図がいちばん広い。スペクトルの一覧 (左) とインスペクター (右) は図の上に浮かぶパネルで、閉じられる
- 道具は図の下の中央に浮かぶ帯。その左に「元に戻す・やり直す」。道具を選ぶと、図の上に一行の使い方 (キーは枠付き)
- 選んだもの (積分など) の真上に小さな帯:「値を変える・基準にする・消す」
- 右のパネルは 解析 / 図 / 記録 の 3 つのタブ。何も選んでいないときは図全体の設定
- 上の帯は ホーム・パネルの開閉・図の名前・操作を探す (Ctrl+K)・Delta との同期の状態・書き出し・図をコピー・設定だけ
- 知らせは元に戻せるものに「元に戻す」を付ける。解決が要るもの (許可・エラー) は消えない
- 何もないときは、次にやることを 1 列に並べ、図がこのパソコンのブラウザに保存されることも書く
- タブレット: 押す所は 44px 以上、初回に「タッチでの操作」を下から出す
- **「時間で見る」のスライダーは入れない** (本人の判断)

## 0. このアプリを何として設計するか (前提)

| 項目 | 内容 | デザインへの意味 |
|---|---|---|
| 何をする道具か | Delta の測定から、週報・論文用の NMR の図を作る。ピーク値・積分を Delta と行き来させる | **成果物は「図」**。画面の主役はキャンバスの図 |
| 誰が使うか | 研究室のメンバー (化学者)。Delta に慣れている。毎日・長時間使う | 初心者向けの説明より、**速さ・密度・予測しやすさ**。ショートカットが効く |
| どこで使うか | Windows の PC (タッチ画面つきを含む)、Chrome / Edge。研究室と自宅 | **デスクトップが主**。タッチでも押せる大きさ。スマホは閲覧程度 |
| 画面の種類 | ホーム (測定の一覧) と 編集画面 (図) の 2 つ + ダイアログ | 情報設計の中心は編集画面のパネル |
| 図の見た目 | Delta に寄せた図 (緑の線、縦書き ppm)。Word / PowerPoint で編集できる SVG | **図の色・フォントは「中身」**。UI の色と混ぜない (デザインシステムの対象外にする) |

カテゴリで言うと「プロ向けの制作・解析ツール」(Figma / Keynote / GraphPad Prism / MestReNova の系統)。
消費者向けアプリや SaaS ダッシュボードの型は合わない。

## 3. UI/UX 監査 (Phase 2)

重要度: **Critical** = 作業が止まる・操作できない人がいる / **High** = 毎回の作業を遅くする・誤りを招く /
**Medium** = 品質・一貫性の問題 / **Low** = 仕上げ

### 3.1 数値で見た一貫性

| 項目 | 実測 | 問題 |
|---|---|---|
| 色 | CSS に 32 種、TSX に 28 種の生の 16 進色。変数は 9 個 | 同じ役割 (警告・成功・選択) に別々の色。図の色と UI の色が同じ層に混在 |
| 文字の大きさ | 12 種 (10 / 11 / 12 / 13 / 14 / 15 / 17 / 18 / 22 px、8 / 9 / 15 pt)。12px が 14 か所、11px が 6 か所 | 階層を作る規則がない。小さい文字が多い |
| 角丸 | 11 種 (0 / 4 / 6 / 8 / 10 / 12 / 14 / 999 px) | 部品ごとにばらばら |
| 余白 | padding の組み合わせ約 30 種、gap 2 / 3 / 4 / 5 / 6 / 7 / 8 / 10 / 12 / 16 | 4 の倍数の刻みになっていない (3・5・7 がある) |
| 影 | 2 種 (ダイアログ・メニュー) | 少なく適切 |
| ボタン | 無指定 58、primary 17、mini 10、mini danger 8、danger 8、icon 5、link 4、chip 3 | 同じ画面に primary が複数 (図をコピー・自動で積分・自動で拾う・記録を付ける) → 「一番やること」が分からない |
| コントラスト (WCAG) | 補助文字 #667085 / 背景 #eef0f3 = **4.36:1** (AA 4.5 未満、しかも 11〜12px)。入力欄の枠 #c3c9d1 = **1.67:1** (部品の境界は 3:1 必要)。薄い灰 #a0a7b1 = 2.43、#999 = 2.85 | 読みにくい・入力欄の境界が見えにくい |
| キーボード | ホームの測定・サンプルのカードが `div` + `onPointerUp` で、フォーカスもキー操作もできない。aria-* は 9 か所 | キーボードだけでは測定を開けない |
| 動き | transition 1 か所。FID の処理 (0.5〜1.5 秒)・2D (3〜5 秒) の間に何も出ない | 固まったように見える |

### 3.3 「AI が作った UI」のチェック

| 観点 | 判定 | コメント |
|---|---|---|
| 意味のないグラデーション | なし | — |
| ガラス風 (glassmorphism) | なし | — |
| 過剰な影 | なし (2 種だけ) | 適切 |
| 巨大な角丸カード | 軽度 | 角丸は 6〜14px。大きくはないが、カードが多い |
| 絵文字の UI | あり (📁 1 か所 + 記号多数) | M4 |
| 過剰な pill / badge | **あり** | M3。状態・絞り込み・測定・図・出どころがすべて丸いチップ |
| 何でもカード | **あり** | スペクトル (左)、サンプル (ホーム)、区画 (右) がそれぞれ枠つき |
| 不要な枠線・区切り線 | **あり** | 区画・カード・入力・表に 1px の枠が重なり、線が多い |
| アイコンの使いすぎ | なし | むしろ文字のボタンが多い |
| 色の使いすぎ | 中程度 | UI の色は控えめだが、生の色が 60 種あり役割が不明確 |
| 画面ごとの不一致 | **あり** | H3 |
| SaaS ダッシュボードのテンプレート感 | なし | — |
| 装飾だけの要素 | 少ない | — |
| 情報量の過剰 | **あり** | H1・M1 (説明文と区画が多い) |

**総括**: このアプリの問題は「AI っぽい派手さ」ではなく、**機能を足し続けたことによる密度の偏りと不統一** (accretion)。
見た目を飾り直すより、**情報設計 (どこに何があるか) とトークン (同じものを同じに)** を整える方が効果が大きい。

### 4.1 「プロ向けの道具が良く見える理由」の言語化

1. **UI が静か**: 枠・色・影が少なく、灰色の濃淡と余白で区切る。色は「中身」(ここでは図) と「選択・一番の操作」だけに使う
2. **揃っている**: 4px の格子に乗り、同じ役割は同じ高さ・同じ余白。密度が高くても雑然としない
3. **階層を箱ではなく文字で作る**: 見出しの太さ・大きさ・色の 3 段階で十分。囲まない
4. **今の作業に必要なものだけ**: 選択に応じてインスペクターが変わる。上級の設定は奥にある
5. **状態がいつも同じ場所に見える**: 保存・同期・進み具合はステータスバー。エラーは消えない
6. **手が覚えられる**: 位置が変わらない。ショートカットがツールチップに出る

## 6. Design Principles (このアプリ専用、案)

1. **図が主役 (Figure First)** — 画面の中心は図。UI は灰色の濃淡で静かにし、色は「スペクトル (データ)」と「選択・一番の操作」にだけ使う。
2. **作業の順に並べる (Workflow Order)** — 開く → 整える (範囲・高さ・基準) → 解析 (ピーク値・積分) → 仕上げ (見た目・注釈) → 書き出す。パネルとツールバーはこの順。
3. **密度は高く、字は読める (Dense, not Tiny)** — プロの道具として情報量は保つ。ただし UI の文字は 14px を基準、13px を下限 (数値の表・補足)。デジタル庁 DS の 16px は採らない (パネルが長くなりすぎる)。その代わりコントラストは AA を必ず満たす。
4. **同じ役割は同じ見た目 (One Role, One Look)** — トークンと部品だけで作る。新しい色・角丸・影・ボタンの種類を足すときは、理由を書いてデザインシステムを拡張してから。
5. **いま必要なものだけ見せる (Progressive Disclosure)** — 選択に応じて中身が変わるインスペクター。上級の設定は折りたたむ。説明文は常時出さず、必要なときに開ける。
6. **状態はいつも見える、データは失わない (Visible State, Safe Data)** — 保存・Delta 同期・処理中はステータスバーの決まった場所。解決が要るエラーは消えずに残る。消す操作は元に戻せる。
7. **キーボードでもタッチでも (Accessible by Default)** — すべての操作にフォーカスとキー操作。押せる大きさはマウス 28px 以上・タッチ 40px 以上。フォーカスの輪は必ず見える。動きは reduced-motion に従う。
8. **Delta の作法を尊重する (Familiar to Delta Users)** — 図の見た目・用語・積分の値は Delta と同じ。慣れた操作を壊さない。
