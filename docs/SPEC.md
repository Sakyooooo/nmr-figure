# NMR Figure Editor 仕様

## 目的
JEOL Delta で処理したスペクトルを、資料 (Word / PowerPoint) 用の図にするまでの手作業をなくす。

| 今の課題 | 解決方法 |
|---|---|
| 不純物 (H₂O, Hexane など) のマーカーを毎回手で描く | 溶媒ごとの不純物表と照合して候補を出し、クリックで付ける。凡例も自動 |
| 貼り付けた図は画像なので後から直せない | 「データ＋描画設定」をプロジェクトファイル (`.nmrfig`) に保存し、図はそこから再生成する |
| Delta は比較した状態を保存できない | 2〜4本の重ね書き・縦並びをプロジェクトごと保存する |
| パワポ上で〇や矢印を付けている | アプリ内で楕円・四角・矢印・線・テキストを描ける。スペクトルに追従する |

## 前提
- 使うのは本人。将来は配布もありうる → サーバーを持たない静的Webアプリ。データはPCの外に出ない
  - 本番の画面には CSP (vite.config.ts) を入れ、外への通信 (fetch・画像・フォーム送信) をブラウザに止めさせる。
    connect-src / img-src は自分のサイトと data: / blob: だけ。eval も禁止 ('wasm-unsafe-eval' のみ)。
    Ketcher が使う paper.js は full 版だと読み込み時に文字列からコードを作る (中の acorn) ので core 版に差し替えている
- 入力は Delta の `.jdf` (処理済み、または未処理の FID)。別ファイルを複数読み込む
- 対象核種: ¹H / ¹³C / ¹⁹F / ³¹P、2D (COSY, HSQC, HMBC, NOESY など全部)
- 比較の用途: 反応の経時変化、原料と生成物。一度に2〜4本
- 見た目: 今の Delta の出力に寄せる (緑の線、下側に縦書きのppm値、下部にタイトル)
- 溶媒ピークの基準値は研究室の慣例に合わせて変更できる (C₆D₆ = 7.15)

## 技術構成
- Vite + React + TypeScript、状態管理は zustand + immer (元に戻す/やり直し)
- `.jdf` の読み込み: `jeolconverter` (MIT)
- 描画: 自前のSVG。画面表示と書き出しに同じ描画を使う
- 不純物表: Fulmer et al., *Organometallics* 2010, 29, 2176 の Table 1 (¹H) / Table 2 (¹³C)

## ppm軸の計算 (検証済み)
`.jdf` の先頭と末尾にはパディングがある。軸は `dataOffsetStart`〜`dataOffsetStop` の点を
`dataAxisStart`〜`dataAxisStop` に対応させて作る。

```
x(i) = axisStart + (i - offsetStart) * (axisStop - axisStart) / (offsetStop - offsetStart)
```

サンプル (C₆D₆) では残存ピークが 7.150 ppm になり、Delta の表示と一致した。
全点を等間隔に割り振る単純な方法だと 7.147 になり、0.003 ppm ずれる。

## 不純物照合
- 期待値 = 表の値 + (研究室の基準値 − 表の残存ピーク値)。例: C₆D₆ は 7.15 − 7.16 = −0.01 ppm 補正
- 許容幅: ¹H ±0.03 ppm、¹³C ±0.3 ppm (変更可)。水・OH・NH は幅を広げる (濃度・温度で動くため)
- 自動では確定しない。候補を一覧にして、ユーザーが選ぶ (例: 1.26/0.86 は Hexane とグリースのどちらも候補)
- 溶媒そのもののプロトン体 (CDCl₃ 中の CHCl₃ など) は候補から外す
- ¹⁹F / ³¹P や研究室固有の不純物 (遊離 P(OMe)₃ など) はユーザーが登録する

## マーカー
- 図を開いたときから色違いのマーカーを 6 つ用意する (名前は空)。名前を入れたものだけ凡例に出す
- 不純物の照合で作られるマーカーは、これまで通り自動で名前が付く

## スキーム (サンプルごと)
- ChemDraw などからの貼り付け・ドロップに加えて、アプリ内で描ける (Ketcher。Apache-2.0)
  - 構造式・反応式を描き、SVG で保存する。描き直せるように MOL / RXN も一緒に残す
  - Indigo (WebAssembly) をブラウザの中で動かすので、外部に送信しない
  - 重いので押したときだけ読み込む (28 MB の別チャンク)。Vite では `process.env` の定義と `events` の別名が要る

## 図に置く構造式・画像
- 位置は図の左上からの割合で持つ (表示範囲を変えても動かない)。ドラッグで移動、右下の角で幅を変える (縦横比は保つ)
- アプリで描いた構造式は SVG の中身をそのまま図に埋め込む (`<g transform>` で拡大縮小)。
  Word / PowerPoint で「図形に変換」すると編集できる。描き直せるように MOL / RXN も残す
- 貼り付けた画像は data URL の `<image>` として置く (Word では編集できない旨をパネルに出す)
- 図の上で Ctrl+V: 画像はそのまま置き、SMILES / MOL らしき文字は構造式エディタで開く

## 注釈 (パワポ風の図形)
- 種類: 楕円・四角・矢印・線・テキスト。色・線幅・破線・塗りを変更できる
- 位置は「どのスペクトルの何ppm・どの高さ」で保存する → 拡大・並べ替え・基準合わせをしてもピークからずれない
- マーカー: 凡例の項目 (不純物・生成物など) を選んで、ピークをクリックして付ける

## ピーク値 (ピークピックアップ)
- 自動で拾う: 表示範囲 (または全体) で、最大ピークの n% (既定 5%) とノイズの 5 倍のうち高い方を超える極大すべて。
  同じピークかどうかはデータ点の間隔で見るので、多重線の隣の線は別のピークとして残る
- 一覧 (peaks.ts) は今のデータから頂点の高さを読み、一番高いピークを 100% として出す。タブ区切り (Excel 用) と値だけの形でコピーできる

## ピーク値ラベルの配置
- 「軸の下」: Delta と同じく、x 軸の下に縦書きで並べ、引き出し線でピークとつなぐ
- 積み重ねのときは、軸の下に出すのは一番下のスペクトルだけ。ほかはピークの上に出す (どのスペクトルの値か分かるように)
- ピークの上にラベルがあるスペクトルは、ラベルの分だけ低く描いて重ならないようにする

## Delta の注釈 (.jdf の中のピーク値・積分)
JEOL の公開仕様ではないので、研究室の実データ 242 ファイル (注釈つき 114) から読み解いた
(読む: lib/jdfAnnotations.ts、書く: lib/jdfWrite.ts、決まりの確かめ: lib/jdfAnnoteCheck.ts)。
- ヘッダの annoteStart (uint64 @1308, BE) / annoteLength (uint32 @1316, BE) が場所を指す。
  場所は常に context の直後 (64 バイト境界とは限らない)。ヘッダ @1203 の最上位ビット (annotationOK) はどのファイルも立っている
- 中身は 352 バイトの見出し + 336 バイト固定長レコード × 枠数 (枠数は見出しの +8、+12 = (枠数+1)×336、先頭は 336)
- レコード (リトルエンディアン):
  | 場所 | 中身 |
  |---|---|
  | +0 float64 | ppm (積分は範囲の中心)。空き枠では uint32 で「次の空き枠」 |
  | +64 / +66 … uint16 | スキップリストの「次」(段 0 / 段 1 …、1 始まりの枠番号、0 = 終わり) |
  | +82 uint8 | 種類。1〜3 = ピーク値、64〜67 = 積分 (最下位ビット = 選ばれている印)。72/74/10 は別の注釈 (このアプリでは扱わない) |
  | +87 uint8 | ピーク 0x02 / 積分 0x12 |
  | +88 float64 | ピークの高さ (その点のデータ値) |
  | +96 float32 | ピークの半値全幅 / 積分の幅 (範囲 = 中心 ± 幅/2) |
  | +128 float64 | 積分の生の値 = 範囲の強度の和 − 点数 × (+328)。**406 件すべてで計算の誤差まで一致** |
  | +136, +316 float64 | Delta の画面の値 = 生の値 × 見出し +224 |
  | +144 float64 | 積分のベースラインの傾き (1 ppm あたり) = (高い ppm 側の端 − 低い側の端) / 幅 |
  | +152 / +154 uint16 | 積分どうしの双方向の鎖 (1 つ新しい積分 / 1 つ古い積分) |
  | +328 float64 | 積分のベースラインの高さ (中心で) = 両端の平均 |
- 端の高さは **端の点を中心に 11 点の平均**。Delta で手で直していない積分 365/406 件でこの決め方と一致 (残りは手で直したもの)
- 見出し: +20 = スキップリストの段の数 / +52 + 2L = 段 L の先頭 / +222 = 一番新しい積分 / +220 = 選ばれている注釈 /
  +120 = 空き枠の鎖の先頭 (空き枠が無いファイルは多くが +120 = +122 = 0) / +224 = 積分の倍率 / +248 = 「この積分を n にする」の n
- スキップリストは **ppm の大きい順**。114 ファイルすべてで、各段が並んでいて輪がなく、上の段は下の段の一部
- **同じ ppm は鎖に 2 つ入らない**: ピークと中心がまったく同じ積分は、Delta 自身が鎖から外している (16 件、積分の鎖には入っている)
- 積分の範囲は ppm ± 幅/2。両端はデータ点の上 (Delta で 1〜2 ppm と 7〜8 ppm に引いてもらったファイルで確認)

## Delta への書き戻し (lib/jdfWrite.ts)
2026-09-19 の版は Delta が開けず断念した。**2026-09-23 に原因が分かった**: +64 を「通し番号」と思い込んで書いていたが、
実際はスキップリストの「次」だった。枠 1 に 1、枠 2 に 2 と書いたため、**レコードが自分自身を指す輪**になり、
Delta が鎖をたどり終わらずに固まっていた。ピークだけのファイルが開けたのに何も出なかったのも、見出し +52 (先頭) が 0 だったため。
積分の +152 にも見本の値 (2) が残っていて、積分の鎖も輪になっていた。

今の書き方:
- 元の .jdf を丸ごと複製し、注釈の場所 (annoteStart 以降) だけ作り直す。測定データ・パラメータには触らない
- 注釈のうしろに 0 以外があるファイルは書き換えない。注釈の場所が無いファイル (処理済みの 7%) は、Delta の空の見出しから作る
- 枠はちょうどの数 (空き枠なし、+120 = +122 = 0)。スキップリストは 1 段 (+20 = 1)。ピーク → 積分 (古い順) の順に並べる
- ppm は必ずデータ点に寄せる。同じ ppm はピークを優先し、積分は Delta と同じく鎖から外す
- 積分は Delta のベースライン (取り込んだものはそのまま、アプリで作ったものは 11 点の平均) で生の値を出し、
  基準の積分からの倍率 (+224) と値 (+248) を書く → **Delta の画面にもアプリと同じ数字が出る**
- 書いたあと jdfAnnoteCheck の決まり (Delta の 114 ファイルがすべて満たすもの) で確かめ、満たさなければ書かない
- 検証: Delta が積分を 2 つ書いたファイルと、同じ積分をこちらで書いたレコードは、種類・印・ppm・幅・つながり・生の値・ベースラインが一致。
  研究室の注釈つき 106 ファイルを「読む → 書く → 読む」で往復して、範囲・値が戻る (値の差 2×10⁻⁵ 以下)
- **実機の Delta での確認待ち** (2026-09-23)。確かめるまでは「Delta へ」ボタンを開発中の画面にだけ出す (lib/features.ts)

## 簡易リッチテキスト
- `^{..}` 上付き / `_{..}` 下付き / `*{..}` 斜体 / `**{..}` 太字 (richText.ts)
- SVG では tspan の baseline-shift・font-style・font-weight で書く。Word/PowerPoint の「図形に変換」でも書式として残る

## PowerPoint の「図形に変換」への対応 (検証済み)
PowerPoint 365 で実際に変換して確かめた結果、次の書き方にしている。
- 上付き・下付きは `baseline-shift` (割合) + `font-size="70%"` で書く。`dy` で上下させると位置がずれて崩れる。
  この書き方だと PowerPoint でも本物の上付き・下付きの書式になる
- 回転した文字に `dy` を付けると、PowerPoint で文字が大きくなる。中心合わせのずれは `translate` に入れる
- 確認用: `scripts/ppt-svg-check.ps1`

## 図のコピー (Word / PowerPoint)
- クリップボードに `image/svg+xml` と `image/png` を両方入れる。Word 365 / PowerPoint 365 は SVG を優先してベクターの図として貼る
  (Word の InlineShape の種類が 17 = SVG になることを確認。PNG だけだと Word が圧縮して荒くなっていた)
- `ClipboardItem.supports('image/svg+xml')` が false のブラウザでは PNG (既定 4 倍) だけを入れ、その旨を表示する
- 確認用: `scripts/word-clip-check.ps1`

## FID の処理 (Delta の処理結果と比べて検証済み)
- 虚部の符号を反転する (しないと Delta と鏡像になる)
- DC 補正 (後ろ 10% の平均) → 指数関数の窓 → ゼロ詰め 2 倍 → FFT → 中央 `x_sweep_clipped / x_sweep` だけ残す
- ppm = x_offset + Hz / refMHz、refMHz = x_freq / (1 + x_offset·10⁻⁶) / 10⁶
- 装置の遅れを 1次位相として先に戻す。時間の原点のずれ = デジタルフィルターの遅れ − 受信の遅れ (点)
  - フィルターの遅れ: パラメーター `orders` / `factors` から (jeolconverter と同じ式。約 19.66 点)
  - 受信の遅れ: `acq_delay` × `x_sweep`。これを入れないと ³¹P (142 kHz 幅) で 1次位相が 840° 近くずれる
- 残りの位相の自動補正
  - ¹H: ACME (1次微分のエントロピー + 雑音の 3 倍を超える負の値への罰則) を 0次 → 0次・1次の順に最小化。1次位相は ±半周期まで
  - ¹³C・³¹P・¹⁹F: 溶媒が飛び抜けて大きくピークがまばらなので、ACME では 1次位相を大きく外す (¹³C の脂肪族が分散形になった)。
    孤立したピーク (ノイズの 20 倍以上、半値幅の 20 倍の範囲で両側が 5% まで下がる) の頂点の位相に、
    12° 以内に乗るピークが最も多い直線を2点から選び (RANSAC)、乗ったピークで当て直して 1次位相とする。
    広がりが全幅の 5% 未満なら 1次位相は 0。0次位相はその 1次位相のもとで ACME を最小にする
  - 1次位相の中心は一番大きいピーク。1次位相の値は「表示範囲の全幅で回る角度」
- ベースライン補正: 1024 区間の中央値にルジャンドル多項式 (5 次) を当て、上に出た点を多項式の値に置き換えながら 30 回繰り返す
- 基準合わせ: 研究室の基準値 ±0.1 ppm (¹H) / ±0.5 ppm (ほか) にある、最大の 20% 以上の線のうち基準値に一番近いもの (¹³C の三重線は中央)
- 検証: Delta の生データと処理版の組 68 組で、Delta の図との相関 ¹H 平均 0.991、¹³C 0.988、¹⁹F 0.962、³¹P 0.875
  (³¹P の低い組は Delta 側の位相がずれていたもの)。¹H の基準のずれは Delta と同じ +0.0585 ppm
- 生データはプロジェクトファイルに保存し、位相・LB・ベースラインの変更はそこから計算し直す (元に戻す/やり直しの対象)

## 推移グラフ
- 追跡する範囲 (ppm) ごとに、両端を結んだ直線をベースラインとして面積 (または高さ) を求め、nH で割る
- 縦軸: 合計を100% / 基準の範囲との比 / 最初の時点を100% / そのまま
- 時間はスペクトルごとに入力。未入力なら名前の最初の数値、それもなければ並び順

## ホーム画面
- フォルダの許可が `denied` のときは requestPermission がダイアログを出さずに拒否を返す (押しても何も起きないように見える)。
  この状態はボタンを「フォルダを選び直す」にし、押したら選び直しのダイアログを出す
- 並びは「測定日 / 名前 / 編集順 (ファイルの保存日時)」× 降順・昇順。設定 (localStorage) に覚える
  - 測定日: 日ごとの見出しを出し、日の中はサンプルを測定時刻順に並べる
  - 名前・編集順: 日の見出しを出さず、同じサンプルの測定を1枚のカードにまとめて並べる (カードに測定日を出す)
- データフォルダは1つ (File System Access API で選び、IndexedDB に覚える)。サブフォルダは読まない
- `.jdf` はヘッダーとパラメーターだけ読む (数十 KB)。結果は IndexedDB にキャッシュ (名前・サイズ・更新日時がキー)
- 測定日時は `actual_start_time` (1990-01-01 UTC からの秒)。jeolconverter のヘッダーの作成日は日がずれるので使わない
- 並びは 測定日 → サンプル (Delta のタイトル) → 実験。スキーム画像・メモ・タグはサンプルごとに IndexedDB に保存

## 積分
- 範囲の強度の和 × 点の間隔。範囲は基準合わせ前の ppm で持つ。両端はそれぞれ一番近いデータ点 (Delta と同じ)
- **両端を結ぶ直線を引いてから足す** (figure.integralBaseline、既定 入)。直線は Delta と同じく「端の点を中心に 11 点の平均」を結ぶ。
  引く分 = 直線の中央の高さ × 点数 (傾きの分は打ち消し合う)。Delta の値と計算の誤差まで一致する (上の「Delta の注釈」)
- Delta から取り込んだ積分は、Delta のベースライン (手で直したものも) をそのまま持つ (Integral.baseline)。範囲を変えたら消して 11 点の決め方に戻す
- Delta の値のそろえ方 (倍率) も取り込む: 見出し +248 と画面の値が合う積分を基準にする (無ければ最初の積分を、その画面の値で)
- 自動積分 (積分パネルの「自動で積分」): detectSignals を核種によらず使う。高さの下限 (既定 3%) と範囲 (全体 / 表示範囲) を選べる。
  すでにある積分と重なる範囲は作らないので、押し直しても手で引いたものは残る
- スペクトルごとに基準 (integralRef) を1つ持ち、その値に比例してほかの値を出す。基準がなければ最初の積分 = 1
- 値の位置: 曲線の上 (Delta 風) / 軸の下にかぎ括弧。積み重ねのとき、軸の下に出すのは一番下のスペクトルだけ

## ピークの高さ
- 小さいピークを見せたいときに全体を引き上げる操作なので、ツールバーに専用の道具を置く (高さツール H)。上下にドラッグで全体の縦倍率、Shift でそのスペクトルだけ。ホイールだけでも変わる
- ツールバーの ↑ ↓ ボタンで 1.5 倍ずつ。タッチだけでも使えるようにするため (Shift やホイールが使えない)
- 選択ツールで背景をドラッグしたときは、最初に動いた向きで決める: 左右 = 表示範囲の移動、上下 = そのスペクトルの倍率 (Shift で全体の縦倍率)
- 上に飛び出した線はプロット領域で切る (Delta と同じ見え方)

## 2D (COSY・HMBC など)
- この研究室のデータに Delta で処理した 2D はないので、生データ (両軸とも Second) だけを読む
- 処理: サインベル窓 → ゼロ詰め → F2 の FFT → 列ごとに F1 の FFT → 絶対値。
  絶対値は位相に影響されないので、位相補正もデジタルフィルターの遅れの補正も要らない (COSY・HMBC の標準的な見せ方)
- F1 は列の複素数を共役にしてから FT する。しないと搬送波を中心に反転した像になる (実データの対角線で確かめた)
- 等高線: 表示範囲を画面の細かさ (1px あたり 1.5 点) に取り直してからマーチングスクエア法。
  縮めるときは最大値でまとめ (弱いピークを消さない)、拡大したときは間を補う
- 等高線の下限の初期値は雑音の 6 倍 (中央値を雑音とみなす)。雑音ばかりのデータでは線が数十万本になるので、
  1本あたり 4万線分を超えたらその高さは描かずに画面で知らせる
- 図は正方形にする (対角線が 45°)。上と右に投影 (表示範囲の最大値)、同じ核種なら対角線を点線で出す
- 2D と 1D は同じ図に混ぜない。図形・ピーク値ラベル・積分・推移グラフは 2D では出さない
- プロジェクトファイルには生データだけを入れ、開くときに FT し直す (処理後の行列は大きいため)

## 保存
- 作業中の図 (doc・スペクトルの中身・保存先のファイル) は IndexedDB に自動保存する。1.2 秒の遅延と、画面を隠したときに書く
  - doc は小さいので変更のたび、スペクトルの中身は開いているものが変わったときだけ書く
  - 起動時に読み戻し、ホーム画面から「編集中の図に戻る」で続きを編集できる
- ファイルへの保存は File System Access API のハンドルを覚えて上書きする。ハンドルも IndexedDB に入れるので、
  ブラウザを開き直しても同じファイルに上書きできる (書き込みの許可は最初の 1 回だけ取り直す)
- ドラッグ&ドロップは `getAsFileSystemHandle()` でハンドルを取り、ドロップした `.nmrfig` にも上書きできるようにする
- 保存先を覚えているときはボタンを「上書き保存」にし、状態 (ファイル名・未保存の変更・自動保存の時刻) を画面の下に出す

## 文献の図 (スクショ) から線幅を読む (lib/trace.ts)
- 列ごとに「いちばん上のインクの点」を拾って波形にする。ベースラインは高さの下から 25% の値
- SI の文の δ の位置で半値全幅を測り、信号ごとの線幅にする (simulate.ts の widthsHz)
- 山の幅が 3 画素より細いときは null にして、既定の線幅を使う (図の解像度＝線の太さしか見ていないため)
- 位置・多重度・J・H 数は SI の文を優先。図は「文から分からないもの」だけに使う

## 文献 (SI) のデータからスペクトルを作る
- 生データがない文献と比べるため、SI の文 (δ・多重度・J・H 数) を読んでローレンツ線で組み立てる (siParse.ts / simulate.ts)
  - 多重度は一次の分裂として二項係数で展開する。J が足りなければ最後の J を使い回す
  - 範囲で書かれた m は、その範囲に均した線の集まりにする。面積は H 数に比例させる
  - 線幅は半値全幅 (既定 ^1H 1.2 Hz、ほか 3 Hz)。実測の線形までは再現しない
- 実測と区別するため、色を変えて (紫) 名前を「文献値から作図 (著者 年)」にする。
  「文献 (著者 年)」だと論文に載っている実測スペクトルに見えるため (2026-09-23 に言い方を変えた)
- 引用元は必須で、図から消せない: タイトルの下に「文献値から作図: 全文」。layout.ts で行を必ず確保する。
  スペクトル名は書き換えられるが、この行は消せないので、実測でないことは必ず図に残る
- 貼られた引用は citation.ts で整える (貼り付け時と入力欄を離れたとき)
  - 改行・行末ハイフン・全角記号・先頭の文献番号を直し、DOI は `DOI: 10.…` に寄せる (`https://doi.org/`・`doi:` は外す)
  - 著者は筆頭のみ「姓, 頭文字」+ et al.。ACS 式・Wiley 式 (頭文字が先)・PubMed 式 (`Smith JA`) を読む
  - 誌名は表引き (正式名と略号の両方を鍵にする)。表になければうしろから略号らしい語を拾い、点を補う
  - 年・巻・頁は ACS 式・PubMed 式・(年) 式・IEEE 式を順に当てる。表題と号は落とす
  - **誌名と年が読めないときは作り直さない** (貼った文をそのまま図に出す)。整えたときは「元に戻す」を出す
  - 書き出しは ACS 風: 誌名と巻は斜体 `*{..}`、年は太字 `**{..}`、頁は最初の頁だけ + 「.」。DOI は図に出さない
  - 著者は ACS 式・Wiley 式・PubMed 式に加えて「Ka Wing Chan; …」のような綴りのままの並びも読む (`;` 区切りなら先頭の 1人)
  - 誌名の鍵からは of / the を落とす (「Journal American Chemical Society」のような貼り付けでも引ける)
  - 整えるのは貼り付けたときと「形を整える」を押したときだけ (手で直した文は触らない)
  - 読み取りは書式を外した文 (plainText) で行う。整えた文をもう一度整えても変わらないようにするため

## 図に入れるもの

## SI 用テキスト
- 多重線の解析は一次の解析 (Hoye ら, J. Org. Chem. 2002, 67, 4014 の J-tree)。線の強度を整数にして合計が 2 のべき乗になるように丸め、
  左端から「まだ説明できていない一番近い線」までを J として木を作る。説明しきれなければ m
- 線の検出: 範囲の最大の 2.5% 以上かつノイズの 6 倍以上の極大。谷がほとんどない肩は線にしない
- 1 本線で半値全幅が 6 Hz を超えるものは br s。1H 以外の一重線は多重度を書かない
- 自動の信号検出 (1H): ノイズの 10 倍以上のピークを 20 Hz 以内でつなげ、両側に 8 Hz 足した範囲を積分にする。溶媒と不純物マーカーは除く
- 表で上書きした値 (多重度・J・H 数・帰属) は積分に保存し、プロジェクトファイルに残る
- 書式: `¹H NMR (400 MHz, C₆D₆[, 296 K]) δ 3.67 (t, J = 5.2 Hz, 18H[, 帰属])`。Word 用は HTML (sup/sub/i)、テキストは Unicode

## ホーム画面の測定のまとめ方
- Delta は生データを `〜-1-1.jdf`、処理して保存した版を `-1-2`, `-1-3` … で保存する
- サンプル名・測定開始時刻・次元・核種・実験名が同じファイルを1つの測定にまとめ、最新の処理版を代表にする
- ダブルクリック/ダブルタップは pointerup の間隔で判定する (タッチでは dblclick が来ない環境があるため)
- 確認はアプリ内のダイアログで行う (埋め込みブラウザでは confirm() が表示されないことがある)
